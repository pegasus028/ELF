# Build decisions (ELF Studio v1.0, WS-F)

Choices made where HANDOVER §3 (WS-F) and §4 left room, roughly in the order they come up.

1. **Same family as the MMI app, different identity.** The fonts are the same (Barlow Condensed + Public Sans), and so are the vanilla JS, the UMD core, the storage wrapper and the projector panel. The MMI app is styled like signage (uppercase, dark corridor bar). ELF Studio is styled like an *application folder*: each room is a coloured folder with a lesson tab (L09…), headings are in sentence case, the paper is a cool tone, and highlighter yellow marks what matters (found clichés, codes, the active task). It has no photos and no figures.
2. **Rooms are plug-ins.** `js/rooms/<room>.js` calls `ELF.registerRoom({key, order, colour, lessons, render, summary, scores, scoreLines})`. Phases 2 and 3 add a file, a `<script>` tag, a `sw.js` entry and a JSON key, and the shell stays as it is. Exit-check cards are generated from the keys of `rooms.exitChecks` (L15+ will appear automatically).
3. **On-screen text.** Every string goes through `t(key, default)`. `uiText` overrides the default, and `tools/uitext.js` keeps `uiText` complete (a test fails if a key is missing). Text that WS-D put in a room (`rooms.x.title`, `intro`, `feedback`, `frames`, `peerPrompt`, `exportHeading`…) takes precedence over the app's generic `uiText` for that room.
4. **Setup keys.** `elf.setup = {name, group, seat, prof}`. The profession comes from `groups[]`. On first run the form is pre-filled from `mmi.setup` (same origin on GitHub Pages).
5. **Line check follows the content.** When `rooms.lineUpgrader.check` gives `numberPattern` and `resultMarkers` (WS-D: digits only; 10 markers), the checker uses them, so the app, the handouts and midterm Part C all apply one rule. Without them it uses a broader built-in rule (number words, "every Saturday", more result markers). The verb has to be the first word. US *-ize* spellings count as the bank's *-ise* forms, and the result marker must come after the verb. Lines under 4 words never pass. *Review fix:* the marker must be followed by at least 3 words. Those words cannot be an evaluation ("was good", "is fun") or a description ("has 30 members"); "has raised 5,000 baht" is accepted. A line with a ban-list cliché, or over `maxWords` (25), does not pass. All 40 WS-D models still pass and all 40 weak lines still fail.
6. **Line plan.** When lines carry `profession`, round 1 is the student's own field and rounds 2–4 take 15 lines from the other fields. The starting point is rotated by group and seat, so seats A/B/C in a trio see different lines from round 2 on. Lines with a `round` field are used as given.
7. **Line Upgrader score.** Score = lines that pass now (/20). Peer stars (sum of 1–3 ratings) are a bonus and appear on the leaderboard (points = passes + stars), but they are not part of the score sent to the gradebook. Editing is free until a round is finished. Finishing locks the round and shows the model upgrades. The gradebook gets the score when round 4 is finished, and again only when the student presses "Send my updated score".
8. **Peer line code (5 chars).** rating · round · line · rater group/seat · day tag · mod-31 check. The rater picks the tag shown on the writer's screen (R2·L3). A student's own code is refused, and a second rating from the same rater for the same line replaces the first.
9. **Result code (8 chars)** = kind · room no. · lesson · score · max · bonus · group · seat · check. Room numbers come from `ROOM_IDS` in `core.js`. Later phases append to that list and never renumber. **Rating code (8 chars)** = kind · 3 criteria · rotation · rater group/seat · session minute · day tag · check. Both use Crockford base32 (O→0, I/L→1 when typed) and reject any single wrong character.
10. **Pitch Clock timing.** The brief says "60 s pitch + 60 s rating per rotation, 4 rotations", and A10 says every student pitches 4 times and gets 4 ratings. So each rotation gives *both* partners a turn: stay line pitches → move line rates → move line pitches → stay line rates, plus a fixed 15-s move (`MOVE_SEC`, like the MMI app's 30-s rotate). That makes 4:15 per rotation and 16:45 for 4, close to the 16-min step in A10. The pitch and rate seconds come from `settings.pitchClock`. Session code: `HHMM` + `P` + optional rotations digit (2–6, default from settings).
11. **Without a session** the Pitch Clock runs a one-turn practice timer, and the rater picks the rotation number by hand.
12. **Ratings are sent by the receiver.** A speaker who adds a partner's code sends one gradebook row (score = total /12). A newer code from the same rater, rotation and session replaces the older one (review fix). Each rating is a separate row because the lesson plan says "ratings posted".
13. **Cliché Hunter.** Every word of the text is a button. A tap inside a span marks the whole cliché, and a tap elsewhere counts as a wrong tap (shown, not scored). "Show the ones I missed" reveals the rest, which then cannot be scored. The ban-list `patterns` (regex) are used when present. A rewrite is accepted when it matches no ban pattern, has at least 6 words, is not the original, is not a cliché already rewritten, and (because WS-D's `rewriteRule` asks for it) contains a digit or a capitalised name/place that does not start a sentence. Score = max(0, found − ⌊wrong taps ÷ 3⌋) + accepted rewrites (/13). The result code's bonus field carries the wrong-tap count (review fix). The app cannot judge whether a rewrite is relevant, so the teacher spot-checks the three.
14. **Evidence Audit flags.** *Unverifiable* = no type, a type with `verifiable:false` / key `none`, or the `link` type with an empty link. *No scale* uses the same number rule as the line check (WS-D: a digit). The C1 "so what" field and the row up/down buttons cover A05's C1 differentiation.
15. **Exit checks** take `mcq` (index or option text as the answer) and `cloze` (typed). Cloze matching ignores case, final punctuation and curly quotes, expands *'ve* / *n't*, and accepts `"a / b"` alternatives and an `accept` list. Students must answer every item before checking. They can retry. Every attempt is saved and sent with its attempt number, and the result code's bonus field carries the attempt number. My scores and the Rooms card show the **first try**, with the best score beside it (review fix). The matcher also strips a subject the stem already has ("I have volunteered"), drops the word that follows the gap ("500 words"), and reads number words ("five hundred").
16. **Storage.** Every read and write is wrapped and an in-memory copy is kept, so with storage blocked the whole app works for the session (tested). Keys used: `elf.setup`, `elf.theme`, `elf.results`, `elf.ratings`, `elf.room.<key>`, `elf.teacher`, `elf.tally`.
17. **Theme.** The toggle cycles auto → light → dark (`elf.theme`). Dark tokens are applied both by `prefers-color-scheme` (unless light is forced) and by `data-theme="dark"`. The projector panel stays dark in both themes.
18. **Phone width.** Below 520 px the brand name and the name chip hide so the three tabs fit on one line; setup is reachable from the Rooms page ("Change"). Every control is at least 44 px (checked by the browser test), the Cliché Hunter words have taller lines, and "Change seat" is a real button on Rooms. The Teacher tab opens without student setup. Below 400 px the Evidence Audit fields use one column.
19. **Service worker** registers only on https and outside frames, serves from the cache first and refreshes in the background, and deletes only older `elf-studio-*` caches (it leaves the MMI app's cache alone on the shared origin).
20. **No build step, no third-party code.** The QR encoder is the MMI app's own, copied unchanged.
21. **Line Upgrader code in one place.** My scores and the trio board both show the live score code, including peer stars.
22. **Result-feedback text** in `rooms.lineUpgrader.feedback.result` names all 10 accepted markers. It was changed in WS-D's source too, so a re-merge keeps it.
